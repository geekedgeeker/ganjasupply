Overview

Introduction

GanjaSupply is a production-quality static web application designed for supply chain management. Built with pure HTML, CSS, and JavaScript, it requires no backend, no build process, no package manager, and no external dependencies. The entire application functions locally and can be hosted as static files on any platform that supports static hosting.

Key Features

  • Static architecture with zero dependencies
  • Premium 420-inspired aesthetic with glass morphism design
  • JSON-based authentication system
  • Editable data tables across all management interfaces
  • Responsive design for desktop, tablet, and mobile
  • Session persistence using browser storage
  • Role-based access control system
  • Professional documentation suite

Installation

Requirements

  • Modern web browser (Chrome, Firefox, Safari, Edge)
  • Text editor for configuration (optional)
  • Web server or static hosting platform

Setup Instructions

Follow these steps to set up GanjaSupply on your local machine or server: 

1. Download or clone the GanjaSupply folder
2. Open the folder in your preferred location
3. Open index.html in a web browser to verify installation
4. Configure UserDB.json with your user credentials
5. Deploy to your hosting platform

Local Development

For local development, you can simply open the index.html file directly in your browser. No server is required for basic testing. For a more realistic development environment, use any static file server: 

Python 3: python -m http.server 8000
Node.js: npx serve
PHP: php -S localhost:8000

Authentication

Authentication Flow

GanjaSupply uses a JSON-based authentication system with session persistence. The authentication flow works as follows:

  1. User enters credentials on sign-in page
  2. JavaScript loads UserDB.json from data directory
  3. Credentials are validated against user records
  4. On success, session data is stored in browser session storage
  5. User is redirected to dashboard
  6. Subsequent pages validate session before loading
  7. Logout clears session and redirects to sign-in

User Database Structure

The UserDB.json file contains all user accounts and role definitions. The structure is designed for easy expansion: 

{
  "users": [
    {
      "id": "unique_identifier",
      "username": "username",
      "password": "password",
      "role": "role_name",
      "created_at": "ISO_timestamp",
      "last_login": null,
      "active": true
    }
  ],
  "roles": {
    "role_name": {
      "permissions": ["permission_list"]
    }
  },
  "version": "1.0.0",
  "last_updated": "ISO_timestamp"
}

Adding New Pages

To add a new page to the application:

  1. Create a new HTML file in the pages directory
  2. Include the CSS link: <link rel="stylesheet" href="../assets/css/main.css">
  3. Include the auth script: <script src="../assets/js/auth.js"></script>
  4. Copy the sidebar structure from existing pages
  5. Add the new page link to all sidebar navigation menus
  6. Implement authentication check in page JavaScript

Adding Users

To add a new user to the system:

  1. Open data/UserDB.json in a text editor
  2. Add a new user object to the users array
  3. Ensure the ID is unique
  4. Set the role to an existing role definition
  5. Save the file

Hosting

GitHub Pages Deployment

GitHub Pages is the recommended hosting platform for GanjaSupply due to its simplicity and zero cost:

  1. Create a new repository on GitHub
  2. Upload the GanjaSupply folder contents
  3. Navigate to repository Settings
  4. Select Pages from the left menu
  5. Choose the main branch as source
  6. Select / (root) as the directory
  7. Click Save and wait for deployment
  8. Access your site at the provided URL

Configuration Requirements

No server-side configuration is required. The application is fully static and will work on any platform that serves static files. Ensure that:

  • All files maintain their directory structure
  • The data directory is accessible
  • JavaScript is enabled on the client
  • Session storage is supported by the browser

Troubleshooting

Authentication Issues
If users cannot sign in, verify that UserDB.json is accessible and properly formatted. Check browser console for JavaScript errors. Ensure session storage is enabled in the browser.
Styling Problems
If styles do not load correctly, verify that CSS files are in the correct directory structure and that file paths in HTML files are correct. Clear browser cache and reload.
Table Editing Issues
Editable table cells use the contenteditable attribute. Changes are currently temporary and not persisted. For data persistence, implement a backend or use local storage with proper serialization.
